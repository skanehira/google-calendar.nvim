1. Introduction                                     *google-calendar-intro*

google-calendar.nvim lets you browse and manage Google Calendar without
leaving Neovim. It renders a month view, a day agenda, and an event detail
card in floating windows, and supports creating, updating, deleting, and
managing Google Meet links.

Calendar operations are delegated to `gws`; the plugin does not call the
Google Calendar API directly.

Features:
  - Month view with previous/next month navigation, today jump, a highlighted
    selected day, and Google Calendar-style event bars and dots
  - Day agenda with colored dots, start times, and event titles
  - Events from multiple configured calendars, merged into one month view
    with automatically assigned calendar colors
  - Google Calendar-style event detail card with attendees, organizer,
    description, and Meet URL
  - Create, update, and delete events
  - Add a Google Meet URL when creating an event, and copy it from the
    detail view
  - In-memory month cache for fast month navigation
  - Configurable window sizes, keymaps, and highlight groups

==============================================================================
2. Requirements                                   *google-calendar-requirements*

  - Neovim 0.10 or later
  - `gws` 0.22.5 or later, installed and authenticated
  - A Google account with the Google Calendar API enabled

Run:
>bash
  gws auth login
<
If `gws` is missing or authentication fails, the plugin reports an error and
does not open the calendar.

3. Setup                                             *google-calendar-setup*

With lazy.nvim:
>lua
  {
    'skanehira/google-calendar.nvim',
    config = function()
      require('google-calendar').setup()
    end,
  }
<
With a manual runtimepath entry:
>lua
  vim.opt.runtimepath:append('/path/to/google-calendar.nvim')
  require('google-calendar').setup()
<
`setup()` is optional. The plugin works with its defaults if you do not call
it.

If you add the plugin to `runtimepath` manually, generate the help tags once:
>vim
  :helptags doc
<

4. Commands                                         *google-calendar-commands*

:GoogleCalendar                                    *:GoogleCalendar*
  Open the current month. If the month view is already open, focus it and
  reuse the cache. Press `r` or `R` in the month view to refetch.

:GoogleCalendar {YYYY-MM}                          *:GoogleCalendar-month*
  Open the specified month. Example: `:GoogleCalendar 2026-11`
  An invalid month such as `2026-13` reports an error and does not open the
  month view.

5. Keymaps                                          *google-calendar-keymaps*

Every key can be changed through `setup()`. Set a key to `false` to disable it.

Month view ~
  h / l              Select the previous / next day
  k / j              Select the previous / next week
  H / L              Go to the previous / next month
  t                  Jump to today
  <CR>               Open the day agenda for the selected day
  a                  Create an event on the selected day
  r / R              Refetch the displayed month
  ?                  Open month view help
  q / <Esc>          Close the month view

Day agenda ~
  j / k              Select an event
  <CR>               Open the selected event
  d                  Delete the selected event
  ?                  Open agenda help
  q / <Esc>          Return to the month view

Event detail ~
  e                  Open the update form
  d                  Open the delete confirmation
  y                  Copy the Meet URL
  g                  Expand or collapse the guest list
  ?                  Open detail help
  q / <Esc>          Return to the agenda

Delete confirmation ~
  y                  Delete the event
  n / q / <Esc>      Close the confirmation without deleting

Create / update form ~
  <Tab> / <S-Tab>    Move to the next / previous composer row
  <CR>               Open the editor for the selected row, or toggle Meet
  <Space>            Toggle all-day or Meet
  :w                 Save (write command)
  <Esc> / q          Cancel. <Esc> leaves insert mode first; q works in
                     normal mode only.
  ?                  Open form help

Form editor ~
  <CR>               Edit the selected date/time field
  :w                 Apply the editor value and close it
  <Esc> / q          Close the editor without applying

Help ~
  q / <Esc>          Close help

The default save command is :w. <C-s> is not used because it conflicts with the
herdr prefix.

6. Configuration                                     *google-calendar-config*

Options and defaults:
>lua
  require('google-calendar').setup({
    -- Additional calendars. primary is always displayed and included first;
    -- omit it here. Prefer the config file below to keep IDs out of dotfiles.
    calendars = { 'work@example.com' },

    -- First day of the week: 'sunday' or 'monday'.
    week_start = 'sunday',

    -- Maximum number of events shown in a month cell (1-10, default 6).
    max_events_per_cell = 6,

    -- Month view size as a ratio of the usable area (excluding the border).
    -- 1.0 fills the available space.
    width = 1.0,
    height = 0.7,

    -- Agenda and detail sizes as ratios of the usable area.
    agenda = { width = 0.5, height = 0.7 },
    detail = { width = 0.5, height = 0.5 },

    -- Date format.
    date_format = '%Y-%m-%d %H:%M',

    -- Path or name of the gws executable.
    gws_cmd = 'gws',

    -- Notification function (replaceable for tests).
    notify = vim.notify,

    -- Clipboard writer (replaceable for tests).
    clipboard = function(url)
      vim.fn.setreg('+', url)
    end,

    -- Per-screen keymap overrides. Use false to disable a key.
    keymaps = {
      month = {
        prev_day = 'h',
        next_day = 'l',
        prev_week = 'k',
        next_week = 'j',
        prev_month = 'H',
        next_month = 'L',
        today = 't',
        agenda = '<CR>',
        create = 'a',
        refresh = 'r',
        help = '?',
        close = 'q',
        esc_close = '<Esc>',
      },
      agenda = { next = 'j', prev = 'k', open = '<CR>', help = '?', close = 'q', esc_close = '<Esc>' },
      detail = {
        edit = 'e',
        delete = 'd',
        copy_meet = 'y',
        toggle_guests = 'g',
        help = '?',
        close = 'q',
        esc_close = '<Esc>',
      },
      form = {
        next_field = '<Tab>',
        prev_field = '<S-Tab>',
        edit = '<CR>',
        toggle = '<Space>',
        save = ':w',
        cancel = '<Esc>',
        close = 'q',
        help = '?',
      },
      confirm = { yes = 'y', no = 'n', close = 'q', esc_close = '<Esc>' },
      help = { close = 'q', esc_close = '<Esc>' },
    },

    -- Highlight overrides.
    highlights = {},
  })
<
Calendar configuration file ~
  To keep calendar IDs out of your dotfiles, put them in
  `stdpath('data')/google-calendar.nvim/config.json` (usually
  `~/.local/share/nvim/google-calendar.nvim/config.json`, normally outside
  a Neovim dotfiles repository):
>json
  {
    "calendars": [
      "work@example.com"
    ]
  }
<
  `primary` is always displayed and cannot be removed. It is automatically
  included first, so you do not need to list it in `calendars`.

  If the file does not exist, only `primary` is used. An empty `calendars`
  array also means `primary` only. If the file is invalid, the plugin warns
  and falls back to `primary`.

  `GOOGLE_CALENDAR_CONFIG` can point to a different file, and
  `setup({ config_file = '/path/to/config.json' })` overrides the path.
  `setup({ calendars = { ... } })` takes precedence over the file when
  explicitly provided.

Keymaps are deep-merged with the defaults. Setting a key to `false` disables
it; unknown screens or actions produce a warning and are ignored.

Example: change the save key and disable `q` in the month view:
>lua
  require('google-calendar').setup({
    keymaps = {
      form = { save = '<A-s>' },
      month = { close = false },
    },
  })
<
`width` and `height` are ratios of the usable area, excluding the float border.
The month view defaults to 1.0 x 0.7 so it stays compact while showing the
configured 6 events per cell. It distributes leftover height across the event rows of each week and
keeps the same size while loading and after data arrives. If the selected
week's rows do not fit, the view scrolls so they are visible. The agenda
defaults to a tall 0.5 x 0.7 window; the detail window defaults to 0.5 x 0.5.

7. Highlights                                     *google-calendar-highlights*

Default highlight groups:
  `GoogleCalendarHeader`          Month title and weekday header
  `GoogleCalendarToday`           Today's date
  `GoogleCalendarSelected`        Selected day number
  `GoogleCalendarSelectedBorder`  Selected cell frame
  `GoogleCalendarSunday`          Sunday dates
  `GoogleCalendarSaturday`        Saturday dates
  `GoogleCalendarOtherMonth`      Dates from adjacent months
  `GoogleCalendarEvent`           Event title text (no background)
  `GoogleCalendarEventTime`       Event time
  `GoogleCalendarCalendarColor1` through `GoogleCalendarCalendarColor11`
                                  Calendar dot colors, assigned by calendars order
  `GoogleCalendarCalendarBg1` through `GoogleCalendarCalendarBg11`
                                  Calendar event bar backgrounds
  `GoogleCalendarDetailTitle`     Detail title
  `GoogleCalendarDetailIcon`      Detail section icons
  `GoogleCalendarDetailMuted`     Detail secondary text
  `GoogleCalendarDetailMeet`      Meet URL in the detail view
  `GoogleCalendarDetailAccepted`  Accepted guests
  `GoogleCalendarDetailPending`   Pending or tentative guests
  `GoogleCalendarDetailDeclined`  Declined guests
  `GoogleCalendarFormTitle`       Composer title
  `GoogleCalendarFormMuted`       Composer placeholder and secondary text
  `GoogleCalendarFormIcon`        Composer section icons
  `GoogleCalendarFormButton`      Composer buttons such as Save
  `GoogleCalendarFormSeparator`   Composer title separator
  `GoogleCalendarBorder`          Float border and month grid separators
  `GoogleCalendarError`           Form errors

Override any group with `setup({ highlights = { ... } })`. Set a group to
`false` to disable it.

8. Behavior                                         *google-calendar-behavior*

Month view ~
  - `primary` plus every additional calendar in `calendars` is fetched and
    merged into the month view. New events are created in `primary`; updates
    and deletes use the event's own calendar ID.
  - The selected day is shown with an orange, bold double-line frame around
    the cell (`GoogleCalendarSelectedBorder`) and an orange date number
    (`GoogleCalendarSelected`). The cell background is not filled; event bars
    and dots keep their calendar colors. The month window title also shows
    `選択: MM-DD`.
  - Month cells use Google Calendar-style event chips: all-day and multi-day
    events are colored bars with white text, and single-day timed events are a
    colored dot followed by the start time and title. Multi-day bars continue
    across adjacent day cells and week rows instead of restarting in each cell.
    Their titles are truncated to the width of the whole bar, not to a single
    cell.
    Calendar colors are assigned automatically in the order `primary`, then the
    entries in `calendars` (11 colors, wrapping).
  - The weekday header is rendered as a fixed `winbar`, so it stays visible
    while the month grid scrolls.
  - Month grid separators use the same `GoogleCalendarBorder` highlight for
    both horizontal and vertical lines.
  - Month data is cached in memory. The cache is cleared when the month window
    closes, when you press `r` or `R`, and after creating, updating, or
    deleting an event.
  - While loading, the header shows `読み込み中...` but navigation, refresh,
    opening the agenda/form/help, and closing remain available. Only the
    latest fetch result is rendered.
  - If the window height is too small, the view scrolls so the selected week
    stays visible.

Day agenda ~
  - Each event uses a colored `●` or `○` dot, the start time, and the title.
    All-day events use an all-day label.
  - The dot color follows the event's calendar color, assigned automatically
    from the order of `calendars`.
  - Events with `status == 'tentative'` or `transparency == 'transparent'` use
    the hollow `○` dot.
  - Locations are not shown in the agenda.

Event detail ~
  - The detail view uses a Google Calendar-style card with the title, date and
    time, location, guests, description, Meet URL, and calendar.
  - Guests are collapsed by default when there are more than five attendees.
    Press `g` to expand or collapse them. The cursor stays in place when
    toggling; collapsing from a guest row moves the cursor to the guest header.
  - Descriptions wrap to the window width and are never truncated. Scroll the
    detail window to read long descriptions.
  - `y` copies the Meet URL to the `+` register. If the event has no Meet URL,
    the plugin reports that instead.

Create / update composer ~
  - The composer uses a Google Calendar-style layout with a main window and
    dedicated editor windows for the title, date/time, guests, location,
    and description.
  - The guests row opens a guest editor. Enter one email address per line;
    duplicates are removed and invalid addresses are reported.
  - The description editor opens at the same size as the main composer.
  - Icons are padded to two display cells, so each row's text starts in the
    same column.
  - <Space> on the date/time row toggles between a timed event and an all-day
    event. <CR> or <Space> on the Meet row toggles Meet.
  - Save from the main composer with :w. Editor windows apply with :w and
    close with <Esc>.

9. Troubleshooting                           *google-calendar-troubleshooting*

`gws` is not found ~
  Install `gws` and make sure it is on PATH. You can also point the plugin at
  an explicit executable:
>lua
  require('google-calendar').setup({ gws_cmd = '/path/to/gws' })
<
Authentication errors ~
  Run `gws auth login` and authenticate with an account that has the Google
  Calendar API enabled.

The month view is too narrow ~
  If the terminal is too narrow for the configured `width`, the plugin reports
  that the window is too small and closes it. Increase `width` or widen the
  terminal.

Keys do not work ~
  Check your `setup({ keymaps = { ... } })` overrides. Setting a key to `false`
  disables it. The guest toggle is `detail.toggle_guests` (default `g`).
