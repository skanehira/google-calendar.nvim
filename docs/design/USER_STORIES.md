### Won't（今回はやらない）

| ストーリー | やらない理由 |
|------------|--------------|
| 複数カレンダーの予定を横断表示する | MVP は primary カレンダー 1 つに絞り、複数カレンダーの表示は将来拡張とする |
| カレンダーの表示/非表示を切り替える | 複数カレンダー表示を前提とするため、MVP では不要 |
| 予定をキーワードで絞り込む | 月表示の一覧性を優先し、絞り込みは将来拡張とする |
| 週表示・日表示に切り替える | MVP は月表示のみ。時間軸のレイアウトは別途の設計が必要 |
| 予定に参加者を追加し招待を送る | 通知の宛先制御と文面の設計が必要で、MVP の価値に対してコストが大きい |
| 繰り返し予定のルールを編集する | RRULE の入力 UI と例外日の扱いが複雑。表示は singleEvents で各 occurrence として行う |
| 予定ごとの色を変更する | カレンダー色の利用で足りるため、MVP では不要 |
| 複数 Google アカウントを切り替える | gws の認証は 1 アカウント前提で、アカウント切替は認証基盤の設計が必要 |
| 通知・リマインダーを設定する | Neovim の外で動く常駐プロセスが必要になり、プラグインの責務を超える |
| 予定データをオフラインキャッシュする | gws を必須とする方針と矛盾し、同期の整合性管理が新たに必要になる |
| 今日の予定をステータスラインに表示する | プラグインの責務を月表示に絞るため、MVP では扱わない |
| Google カレンダー自体の作成・削除・共有設定 | カレンダーの管理は Google カレンダーの UI の領域で、MVP の予定 CRUD に不要 |
