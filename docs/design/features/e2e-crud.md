# E2E の CRUD 通し検証

- 種別: 機能設計書
- 対象 UC: なし (基盤)

## 何を作るか

headless Neovim で月表示を開き、キー入力（`nvim_feedkeys`）と非同期完了の待機（`vim.wait`）を使って予定の作成・更新・削除を通しで検証する E2E シナリオを提供する。偽 gws（[test-harness.md](test-harness.md)）を使い、実カレンダーは変更しない。`make test-e2e` で実行する。

## 入出力と振る舞い

**シナリオ**:

1. 一時ディレクトリに偽 gws の状態ファイルを作る（予定 0 件）
2. headless Neovim で `setup({ gws_cmd = <fake> })` を呼び、`:GoogleCalendar` を実行する
3. 月表示が開き、日付セルが描画されることを assert する
4. `a` で登録フォームを開き、タイトルと日時を入力して `<F2>` を押す
5. フォームが閉じ、月表示の該当セルに予定が表示されることを assert する
6. 偽 gws の状態ファイルに予定が 1 件追加されていることを assert する
7. 予定の詳細を開き、`e` で更新フォームを開き、タイトルを変更して `<F2>` を押す
8. 月表示の該当セルに新しいタイトルが表示されることを assert する
9. 詳細を開き、`d` → `y` で削除する
10. 月表示から予定が消え、偽 gws の状態ファイルが 0 件になることを assert する

**実行**:

```bash
make test-e2e
```

- `scripts/e2e.sh` が `FAKE_GWS_STATE` と `XDG_STATE_HOME` を一時ディレクトリに設定する
- 失敗時は非 0 で終了し、どのステップで失敗したかを stderr に出す
- 成功時は 0 で終了する

**アサーション**:

- バッファの行・extmark・virt_lines の内容
- 偽 gws の状態ファイルの予定件数と `summary` / `start` / `end`
- フォームの入力値とエラー表示
- 削除確認の表示と `y` / `n` の分岐

## エッジケースの決定

- **空・最小データ**: 予定 0 件の状態から開始し、作成後に 1 件、削除後に 0 件になることを検証する
- **上限・境界値**: 予定 4 件以上の日を作り、セルに `+N` が表示されることを検証する。日付は月末・月初をまたぐケースを含める
- **エラー時に利用者へ見えるもの**: 偽 gws の認証エラー fixture を使い、月表示が開かず通知が出ることを検証する。作成失敗時にフォームが閉じないことを検証する
- **並行操作・二重実行**: 保存中の `<F2>` 連打を再現し、偽 gws の呼び出しが 1 回だけであることを検証する
- **再表示時の整合**: 作成・更新・削除の後に月表示を再取得し、状態ファイルとバッファ内容が一致することを検証する
