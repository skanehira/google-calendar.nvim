# 月表示

- 種別: 機能設計書
- 対象 UC: UC-001 (docs/design/USECASES.md)

## 何を作るか

Google カレンダーの月表示を Neovim の float window に描画する。月タイトル、曜日ヘッダー、6 週×7 日の日付セル、セル内の予定チップ（既定 6 件、設定可能、超過は `+N`）を表示し、`h` / `l` / `j` / `k` で日を移動、`H` / `L` で前月・次月、`t` で今日へ移動する。`:GoogleCalendar [YYYY-MM]` で開く。予定の取得は `config.calendars` の各カレンダーについて `gws` の `events.list` を `singleEvents=true` で呼び、結果を統合する。`nextPageToken` があれば追加取得する（[DESIGN.md](../DESIGN.md)「既知の制約」参照）。

## 入出力と振る舞い

**画面レイアウト**:

```text
╭─ Google Calendar — 2026年10月 — 選択: 10-28 ────────────────╮
│ 日      │ 月      │ 火      │ 水      │ 木      │ 金      │ 土      │
│─────────┼─────────┼─────────┼─────────┼─────────┼─────────┼─────────│
│      27 │      28 │      29 │      30 │       1 │       2 │       3 │
│         │         │         │         │         │         │         │
│         │         │         │         │         │         │         │
│         │         │         │         │         │         │         │
│         │         │         │         │         │         │         │
│─────────┼─────────┼─────────┼─────────┼─────────┼─────────┼─────────│
│ ...                                                               │
╰───────────────────────────────────────────────────────────────────╯
```

**複数カレンダー**:

- カレンダー ID は `stdpath('data')/google-calendar.nvim/config.json` から読み込む。ファイルがなければ `primary` を使う
- `primary` と `config.calendars` の追加カレンダーを取得し、予定を 1 つの月表示に統合する。`primary` は常に含まれる
- 予定モデルの `calendar_id` を保持し、詳細のカレンダー表示、更新、削除に使う
- 新規作成は `config.calendars[1]` に対して行う
- いずれかのカレンダーの取得に失敗した場合はエラーを通知し、既存の表示を維持する

**操作 → 振る舞い**:

| 操作 | 振る舞い |
| --- | --- |
| `:GoogleCalendar` | 当月の月表示を開く。既に開いている場合はメモリ上のキャッシュを使ってフォーカスする（再取得は `r` / `R`） |
| `:GoogleCalendar 2026-11` | 指定した月の月表示を開く。不正な形式は通知して開かない |
| `h` / `l` | 選択日を前日 / 翌日へ移動する。月の境界を越える場合は表示月も切り替える |
| `j` / `k` | 選択日を前週 / 翌週へ移動する。月の境界を越える場合は表示月も切り替える |
| `H` / `L` | 前月 / 次月へ移動し、選択日は同じ日付（存在しない場合は月末）にする |
| `t` | 今日を含む月へ移動し、今日を選択する |
| `<CR>` | 選択日の日別アジェンダを開く（[event-detail.md](event-detail.md)） |
| `a` | 選択日の登録フォームを開く（[event-create.md](event-create.md)） |
| `r` / `R` | 表示中の月を再取得する（キャッシュを破棄する） |
| `?` | ヘルプを開く（[help.md](help.md)） |
| `q` / `<Esc>` | 月表示を閉じ、元のウィンドウへ戻る |

**描画の決定**:

- float のサイズは、ボーダー 2 列/行を除いた利用可能領域に対する `config.width` / `config.height` の比率で決める（既定 1.0）。幅は `7 * cell_w + 6` に丸める。再描画時は現在のウィンドウ幅ではなく設定値から `cell_w` を計算し、予定の削除などで幅が変わらないようにする。高さは `1 + 6 週分の日付行 + 6 本の横線 + 6 * (max_events_per_cell + 1)` を最低限とし、余った高さを各週の空の予定行に配分する。取得中と取得完了でサイズは変わらない。画面に収まらない場合は選択中の週の予定行が見えるようにスクロールする
- セル幅は `cell_w = floor((target_width - 6) / 7)`。7 セルを `│` で区切り、各週の上に `─` / `┼` の横線を引いてセルのグリッドを作る
- 各週は「日付行 1 行 + 予定行 `max_events_per_cell + 1` 行」のブロック。予定行は常に `max_events_per_cell + 1` 行描画し（予定がない週も空行で埋める）、7 セル分のチャンクを横に並べる。これにより取得中と取得完了でウィンドウの高さが変わらない
- 日付行は ` 1`〜`31` の右寄せ。今日は `GoogleCalendarToday`、選択日は `GoogleCalendarSelected`（オレンジ・bold）、日曜は `GoogleCalendarSunday`、土曜は `GoogleCalendarSaturday`、前月・翌月は `GoogleCalendarOtherMonth` でハイライトする
- ウィンドウの高さは「ヘッダー 1 行 + 6 週分の日付行 + 6 本の横線 + 6 * (max_events_per_cell + 1) 行」の固定値。幅は 7 セル + 6 本の区切り線に合わせる。右側に空白を残さない
- 月タイトルは `FloatTitle`、float のボーダーは `FloatBorder` を `winhl` で `GoogleCalendarHeader` / `GoogleCalendarBorder` に割り当てる
- 選択中のセルは背景を塗らず、オレンジ・bold の二重線フレーム（`GoogleCalendarSelectedBorder`）で囲む。日付は `GoogleCalendarSelected` でオレンジにする。予定バー・ドットはカレンダー色を保つ。ウィンドウタイトルにも `選択: MM-DD` を表示する
- 予定チップは Google カレンダー風に表示する。終日・複数日予定はカレンダー色のバー（白文字、時刻付き複数日は `HH:MM タイトル`）、単日の時刻付き予定はカレンダー色の `●` / `○` ドット＋`HH:MM`＋タイトル。タイトルはセル幅に合わせて `…` で切り詰める
- 複数日予定は週内の列を跨ぐ行に割り当て、隣接セルの `│` をバー背景で覆って連続表示する。週をまたぐ場合は次の週の行にも続けて表示する。バーのタイトルはバー全体の幅に合わせて切り詰め、1 セル幅で省略しない。選択セルのフレーム境界では `┃` を優先する
- カレンダー色は `primary` を先頭に、続いて `config.calendars` の順で 11 色を自動割り当てする（12 件目以降は先頭に戻る）。`GoogleCalendarCalendarColorN` がドット、`GoogleCalendarCalendarBgN` がバー背景
- 予定が `max_events_per_cell` を超える日は、`max_events_per_cell` 件までを表示し、最後の行に `+N` を表示する
- 予定がない日もセルの高さを固定するため、空の予定行を `max_events_per_cell + 1` 行描画する
- ヘッダーに `読み込み中...` を表示するが、取得中も移動・再取得・アジェンダ/フォーム/ヘルプを開く・close は受け付ける
- 予定の並び順は終日予定を先頭、その後を開始時刻の昇順にする

**データ**:

- 取得範囲は月初を含む週の開始曜日から 42 日。`timeMin` は範囲の 0 時、`timeMax` は範囲の翌日 0 時（ローカルオフセット付き RFC3339）
- 時刻付き予定は開始日から終了日まで、終日予定は開始日から終了日の前日まで各日に載せる
- 予定は `events_by_date` に `YYYY-MM-DD` をキーとして保持する
- 取得済みの月は `state.month_cache[YYYY-MM]` に保持し、同じ月へ戻るときは `gws` を呼ばずに再利用する。月表示を閉じるか、`r` / `R` で再取得するとキャッシュを破棄する

キーマップは `config.keymaps.month` から解決し、`setup()` で上書きできる。閉じる `q` / `<Esc>` は `month.close` / `month.esc_close` で別々に変更・無効化できる。

## エッジケースの決定

- **空・最小データ**: 予定が 0 件の月もエラーにせず、セル高さを固定するため空の予定行を描画する
- **上限・境界値**: 月初が日曜の場合は 1 週目が月初から始まる。月初が月曜以降の場合は前月の日を埋める。常に 6 週（42 日）を描画する。2 月・閏年・30 日の月も同じ計算で扱う。セル幅が 7 未満になる場合は描画を諦め、`Window is too narrow` と通知する
- **エラー時に利用者へ見えるもの**: gws の API エラー時はエラー内容を通知し、取得済みの表示があれば維持する。初回で失敗した場合は空の月表示を開かず、通知だけを出す
- **並行操作・二重実行**: 取得中は `loading = true` として `読み込み中...` を表示するが、移動・再取得・opener・close は受け付ける。月移動を連続で行った場合は最後の要求だけを反映する（要求 ID を保持し、古い応答を破棄する）
- **再表示時の整合**: `r` / `R` または予定の変更後に表示中の月を再取得する。再取得後も選択日を維持する。他者による変更は `r` / `R` で反映する。同じ月への移動ではメモリキャッシュを使い、ウィンドウを閉じると破棄する
